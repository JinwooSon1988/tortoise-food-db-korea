# English site translations

The English site (`/en/`) is generated by `scripts/generate_en_pages.py` (plant pages) and `scripts/en_hubs.py`
(home, all plants, core foods, guides) from the same canonical data as the Korean pages. Facts are never stored twice:
only wording is translated.

- `strings_en.json` — `{sha1(korean)[:16]: {"ko": korean, "en": english}}` for every Korean data string shown on an
  English page. A changed Korean source string gets a new key, so stale translations cannot be used silently.
- `catalog_en.json` — generated; English names, reasons and roles used by the English search and plant list.
- English text already stored in the data (evidence summaries, scopes) is shown as written, apart from the
  display-only repairs listed in `POLISH` / `ANIMAL_EN` in `scripts/i18n_en.py`.

Workflow when Korean data changes:

1. `python scripts/generate_en_pages.py --collect` writes `_missing.json` (untranslated Korean strings) and
   `_passthrough.json` (English data strings, for review). A normal run fails while anything is untranslated.
2. Translate the missing strings into a `{key: english}` JSON file and run
   `python scripts/i18n_en_merge.py <file>`; the merge checks keep Latin names, numbers and grade codes.
3. Re-run the generator and `python scripts/qa_english_site_v1.py`.
