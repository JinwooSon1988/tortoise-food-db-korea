# 거북밥 UI/UX 제품 설계 기준 v1 (2026-10-08)

## 제품의 역할
육지거북의 식물 먹이 급여 판단을 위한 근거 중심 의사결정 도구. 특정 거북 종 전용이 아니다. 종 선택을 강요하지 않으며 종별로 중요한 예외만 결과에 표시한다.

## 첫 5초: 질문 → 답
1. 홈에서 검색 입력창을 가장 먼저 인지한다. 검색 예시·등급별 보기·불필요한 기능을 앞세우지 않는다.
2. 결과의 첫 시선은 **식물명 + 학명 + 실제 식물 이미지 + 급여 등급 및 설명**이다.
3. 두 번째 시선은 **왜 이 판정인가**, **급여 부위**, **중요한 위험·예외**다.
4. 근거 원문·영양 수치·연구 한계는 상세 화면에서 점진적으로 공개한다. 다만 제한·회피 판정의 핵심 이유와 안전 경고는 절대로 접지 않는다.

## 신뢰성 계약
- 영양성분, 논문, 식물명, 식물 부위, 가공 상태, 종 적용범위, 원문 링크는 서로 구분하여 추적 가능해야 한다.
- 식물의 일반적인 영양성분만으로 안전 급여 판정을 자동 변경하지 않는다.
- 식물 이미지가 검증되지 않았다면 다른 종의 이미지를 대신 표시하지 않는다.
- 근거가 부족하면 그 부족함을 명확하게 표시한다. 등급과 근거 수준을 혼동하지 않는다.
- 연구 대상 종·아종에 한정된 결과는 그때만 예외를 명시한다.

## 정보 구조
**홈:** 브랜드/가치 제안 → 검색 → 결과 → 필수 안내 → 부가 탐색
**결과 카드:** 사진/이름/학명 → 판정 → 판정 이유 → 부위/주의 → 상세 근거 링크
**상세 페이지:** 판정 요약 → 핵심 이유·주의 → 실제 급여 가이드 → 영양·근거·한계 → 원문 출처
**전체 식물:** 검색/필터/목록 → 동일한 등급 용어와 시각적 표기
**연구 방법:** 평가 원칙·출처·불확실성의 명확한 설명

## 시각적 시스템
- 차분한 숲색, 중립 배경, 충분한 대비; 등급 색상은 보조 수단이고 반드시 등급 문자와 설명을 병기한다.
- 검색/판정/위험/근거의 시각적 위계가 모든 화면에서 일관되어야 한다.
- 모바일에서는 가로 넘침과 작은 터치 영역을 제거하고, PC에서는 과도한 빈 공간을 줄인다.
- 이미지가 없거나 실패할 때도 핵심 판정 정보의 레이아웃은 유지한다.
- 과도한 장식, 근거 없는 신뢰 수치, 불필요한 CTA 및 반복 문구를 추가하지 않는다.

## 출고 품질 게이트
1. 검색 → 결과 → 상세 → 홈/뒤로 동작 테스트.
2. 320px·375px·768px·1280px 화면에서 가로 넘침·잘림·터치 타깃 확인.
3. 키보드 포커스, 접근성 이름, 상태 알림, 색상 대비, 축소 동작 설정 확인.
4. 제한·회피 판정 이유가 접히지 않았는지 자동 테스트.
5. 식물명·학명·이미지·급여 부위·출처 일치 검증.
6. 기존 QA와 GitHub Pages 배포 성공 확인. QA 실패는 신규/기존 구분하되 방치하지 않는다.

## 성과 지표(목표, 검증 전)
- 검색 후 판정 인지: 5초 이내
- 제한 이유 이해: 10초 이내
- 핵심 경고: 추가 클릭 없이 확인
- 원문 출처 접근: 결과에서 2회 이내
- 위 지표는 실제 사용자 테스트로 검증하고 개선한다.

## 구현 우선순위
P0: 실제 사용자 검색/판정/안전 경고 흐름과 동작 정확성
P1: 홈·결과·상세·전체 목록의 디자인 시스템 통일
P2: 실제 식물 이미지와 학명 검증, 모바일/PC 사용성
P3: 고급 영양·연구 근거 탐색과 국제화

> 이 문서는 디자인 의사결정 기준이다. 실제 구현 완료 또는 사용자 테스트 완료를 의미하지 않는다.
