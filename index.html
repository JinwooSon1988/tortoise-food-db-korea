v5.0 RC1 통합검수
66종 상세페이지, 검색, 다개체 프로필, 오늘 식단, 개체별 7일 기록, 백업·복원, PWA를 하나의 릴리스 후보로 통합 검수했다.
PWA·오프라인 v4.9
홈·프로필·오늘 식단·7일 기록·백업 화면을 앱처럼 설치 가능한 PWA 구조로 묶고, 핵심 화면을 오프라인 캐시한다. 방문하지 않은 상세페이지는 연결이 필요하다는 오프라인 안내도 추가했다.
백업·복원 v4.8
프로필과 식단 기록을 JSON으로 백업·복원할 수 있게 했다. 복원 파일은 schema/version/기본 구조를 먼저 검사하고, 기존 데이터 교체 전에 사용자 확인을 요구한다.
개체별 7일 분석 v4.7
7일 식단을 ‘현재 거북만 / 모든 거북 / 과거 미지정’으로 분리했다. 삭제도 화면 순번이 아니라 event ID 기준으로 바꿔 다른 개체 기록이 잘못 지워지는 문제를 방지했다.
다개체 프로필 v4.6
한 마리뿐 아니라 여러 육지거북을 등록하고 ‘현재 거북’을 선택할 수 있게 확장했다. 새 7일 식단 기록에는 안정적인 개체 ID가 함께 저장된다.
내 거북 프로필 v4.5
종·성장단계·체중·사육방식 프로필을 등록하고 7일 식단 화면과 연결했다. 종별 근거가 없는 경우 프로필 때문에 판정을 임의 변경하지 않는다.
7일 식단 기록 v4.4
최근 7일 식단 기록을 추가했다. 먹인 식물·반복횟수·서로 다른 식물 수를 브라우저에만 저장하고, 반복을 곧바로 위험/결핍으로 진단하지 않는다.
오늘 식단 도구 v4.3
사용자가 실제로 먹이 여러 종을 선택해 현재 검증상태를 한 번에 비교하는 오늘 식단 빠른 분석 페이지를 추가했다. 근거 없는 임의의 종합점수는 만들지 않는다.
블로그↔DB 유입루프 v4.2
66개 식물 상세페이지에 breadcrumb·관련 먹이 5개·프로필 검색 복귀 링크를 넣었다. 네이버 글에서 쓸 수 있는 66종 딥링크 앵커 데이터도 생성했다.
전체 식물 SEO 페이지 확장 v4.1
plant master에 등록된 66종 전부에 정적 상세 URL을 생성했다. 검증이 덜 된 식물은 U 상태 그대로 공개해 검색 노출을 위해 판정을 조작하지 않는다.
검색 UX 안정화 v4.0
한글 자모 기반 오타검색, 최대 3개 후보, 키보드 이동/선택, 자동교정 금지, “검색 후보 ≠ 식물종 동정” 경고를 실제 검색 레이어에 적용했다.
한글 오타검색 LIVE 연결 v3.9
민드레→민들레, 뽕닢→뽕잎, 질갱이→질경이처럼 오타 후보를 최대 3개까지 제안한다. 자동교정은 하지 않으며 사용자가 직접 후보를 선택해야 한다.
영양값 3중 교차검증 v3.8
로메인 FDC 746769과 케일 FDC 323505를 각각 3개의 USDA-derived 데이터 표현에서 교차검증했다. 서로 다른 record/release의 값은 평균내지 않는 규칙도 추가했다.
Foundation 영양값 교차검증 v3.7
로메인 FDC 746769은 Ca 35/P 30mg(Ca:P 1.17), 케일 FDC 323505는 Ca 254/P 55mg(Ca:P 4.62)로 교차검증했다. 다만 공식 원자료 직접 추출 전이므로 official_direct 승격은 보류한다.
공식 영양 record 후보 확보 v3.6
로메인 FDC 746769(Foundation), 케일 FDC 323505(Foundation), 치커리 FDC 169992, 엔다이브 FDC 168412를 record-level 후보로 확보했다. 후보 단계에서는 4/4로 승격하지 않는다.
우선 10종 검증판 확장 v3.5
클로버·알팔파·엔다이브·로메인·뽕잎까지 동일한 evidence/release 체계에 편입했다. 이제 우선 10종 전체를 하나의 검증 대시보드에서 추적한다.
판정 설명가능성 v3.4
핵심 5종에 “왜 이 배지인가?” 데이터층을 추가했다. 사용자가 초록·노랑·U 결과만 보는 것이 아니라 근거와 남은 blocker를 바로 확인할 수 있다.
핵심 먹이 검증 확장 v3.3
치커리·아욱·방가지똥을 다음 editorial queue에 올렸다. 아욱은 한국 판매명과 해외 Malva 근거를 자동 동일시하지 않고 식물동정을 최우선 blocker로 둔다.
질경이 판정 후보 v3.2
🟡 혼합급여 지지근거 있음 · 공식 영양자료 검증 중. Mediterranean Testudo 관리자료와 Plantago 섭식근거는 있지만, 정확한 Plantago 종과 공식 영양 record가 아직 연결되지 않아 민들레와 같은 초록 판정으로 올리지 않았다.
최초 최종판정: 민들레 v3.1
🟢 혼합급여 적합으로 editorial review를 통과했다. 단독 주식·무제한 급여 판정이 아니며, 한국의 ‘민들레’가 USDA record의 Taraxacum officinale와 동일한지는 별도 동정이 필요하다.
최초 4/4 데이터: 민들레 v3.0
USDA 공식 SR Legacy record FDC 169226(NDB 11207)을 연결했다. 생것 100g 기준 Ca 187mg, P 66mg, Ca:P 약 2.83이다. SR Legacy임을 명시하며 Foundation 데이터로 둔갑시키지 않는다. 최종 공개 급여판정은 별도 editorial review를 거친다.
공식데이터 투입 자동화 v2.9
공식 record가 확보되면 코드 수정 없이 staging 검증 → nutrition record → gate 재검사로 이어지는 승격 절차를 준비했다. 검증되지 않은 후보는 승격되지 않는다.
4/4 직전 데이터 검증 v2.8
민들레·질경이의 공식 영양 record를 production DB에 바로 넣지 않고 staging → identity → basis → nutrient → 승인 절차를 거치도록 했다.
민들레·질경이 위험성 검토 완료 v2.7
6개 위험성 축을 모두 검토했다. 다만 ‘근거를 찾지 못함’은 ‘안전이 증명됨’이 아니다. 두 식물의 현재 핵심 병목은 공식 영양 record다.
출처 재검증 v2.6
PubMed DOI/PMID와 USDA 2026 Foundation release를 다시 대조했다. 공식 record를 찾지 못한 식물은 빈칸을 억지로 채우지 않고 gap ledger에 남긴다.
위험성 문헌 검토 v2.5
민들레·질경이부터 옥살레이트·질산염·식물 독성 문헌을 연결했다. 사람·가축 대상 화학자료를 이베라의 독성 한계치로 오용하지 않는다.
근거를 바로 읽는 상세페이지 v2.4
식물 상세페이지에서 연구 대상종·근거 수준·무엇을 의미하는지·어디까지 해석하면 안 되는지를 함께 보여준다.
검색엔진용 식물 상세페이지
우선검증 식물 10종은 각각 독립 URL 구조를 갖는다. 검색 결과에서 바로 식물 상세정보로 진입할 수 있도록 준비했다.
검색 안전장치 v2.2
오타는 “혹시 이것을 찾으셨나요?” 후보로만 제시한다. 자동으로 다른 식물로 바꾸지 않으며, 통칭이 여러 종을 가리키면 사용자가 후보를 선택해야 한다.

이베라 우선 검증
T. graeca 종 수준 근거와 T. g. ibera 직접근거를 구분한다. 야생섭식 또는 영양성분만으로 권장판정을 만들지 않는다.
이베라 연구 연결 v1.7
T. graeca 야생식이 논문과 지중해거북 전문 사육지침을 식물별로 연결했다.
T. g. graeca 자료는 T. g. ibera 직접근거가 아니므로 별도 계층으로 표시하며, 자동 급여승격에는 사용하지 않는다.
현재 베타 상태
공식 record 자동승인은 금지되어 있다. 검색엔진이 다른 식품 상세 페이지를 반환할 수 있으므로 페이지 본문의 식품명까지 일치해야 승인한다.

공식 K-FIND는 원재료·가공식품·음식의 영양 DB와 다운로드 기능을 제공한다. 그러나 이 빌드에서는 개별 채소의 공식 record ID를 확인하지 않은 상태에서 숫자를 자동 채우지 않는다.
